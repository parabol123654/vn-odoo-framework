# Odoo 17 CE itself is installed separately; see the upstream install guide.
#
# vn_core and l10n_vn_vas_reports currently need no Python package beyond what
# Odoo 17 already requires. The Domain layer deliberately depends on nothing
# outside the standard library.
#
# OCA dependencies are Odoo *addons*, not pip packages. Either clone the repos
# into addons_path (see scripts/odoo.conf.example):
#
#   OCA/reporting-engine            report_xlsx, report_xlsx_helper
#   OCA/queue                       queue_job
#   OCA/account-financial-tools     account_asset_management  (fixed assets —
#                                   account_asset is Enterprise-only in 17)
#
# ...or install them from PyPI, which puts them on addons_path automatically:
#
#   odoo-addon-report-xlsx>=17.0dev,<17.1dev
#   odoo-addon-queue-job>=17.0dev,<17.1dev
#   odoo-addon-account-asset-management>=17.0dev,<17.1dev
#
# All of them must come from the 17.0 branch. An addon from another series
# installs and then fails on a field that moved.

# Excel export. Deliberately not pinned here: whatever Odoo 17 installs is what
# runs, and Odoo 17 pins XlsxWriter==3.0.2 (3.1.9 on Python 3.12).
#
# The floor below stays at 1.1.2 on purpose. scripts/check_repo.py holds the
# code to the 1.1.2 method surface unless a call is feature-detected, because
# a server's wheel is often older than the Odoo it serves — that mismatch is
# exactly how Worksheet.ignore_errors once shipped and raised in production.
# Nothing is added to the server's dependencies by this framework.
XlsxWriter>=1.1.2
